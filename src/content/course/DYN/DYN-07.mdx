## The problem with solving once

DYN-04's trajectory optimization produces a single, complete trajectory $q_{0:T}^*$ by solving the finite-horizon problem once, at $t=0$, from the assumed initial state. Executing that trajectory **open-loop** (blindly playing out the precomputed controls, ignoring what the robot actually does) is fragile for an entirely practical reason: the assumed dynamics $x_{t+1}=f(x_t,u_t)$ are never exactly right (unmodeled friction, an inaccurate mass estimate, an external push), so the *actual* state $x_t$ drifts away from the planned $q_t^*$ as $t$ grows, and the precomputed controls, tuned for a trajectory the robot is no longer on, become increasingly wrong.

## The receding-horizon principle

The fix is exactly DYN-05's timing-optimal control idea, generalized from a single scalar decision ($\tau$) to a whole trajectory: **re-solve the optimization at every control cycle, using the actual current state as the new starting condition**, and only ever execute the very first control of each solve.

```
MPC(current state x, horizon H, dynamics f, cost terms f_t, constraints g_t,h_t):
  loop forever, at every control cycle:
    1. measure/estimate the actual current state x
    2. solve DYN-04's finite-horizon problem over the next H steps,
       starting from x_0 = x:
         min_{x_1:H, u_0:H-1}  sum_t ||f_t(x_{t-k:t})||^2
         s.t.  x_{t+1} = f(x_t, u_t),  g_t(x_t) <= 0,  h_t(x_t) = 0
    3. apply only u_0*, the first control of the solved sequence
    4. discard the rest of the plan; advance one step; go to 1
```
*(Newly authored, synthesizing DYN-04's finite-horizon problem into the standard receding-horizon control loop; see Rawlings, Mayne & Diehl, Model Predictive Control, Ch. 1 for the general algorithm this instantiates.)*

## MPC is a closed-loop policy

Re-solving with the *true* current state $x$ at every cycle means the control actually applied is a function of the current state alone, $\pi_{\text{MPC}}(x,t):=u_0^*(x)$ (the first control from a fresh horizon-$H$ solve starting at $x$): this is **exactly** DYN-06's closed-loop structure $\dot x=f(x,\pi(x,t))$, not an open-loop control sequence. Framed this way, MPC is doing for a full nonlinear trajectory-optimization problem what LQR already does for the linear-quadratic special case (DYN-04): both produce a state-feedback policy $u^*(x)$, LQR by solving the Riccati equation once in closed form, MPC by re-solving a (generally nonlinear, constrained) optimization at every step because no closed form exists in general.

## Horizon length, terminal cost, and warm-starting

Three practical design choices connect directly back to earlier modules:

- **Horizon length $H$**: a short horizon is cheap to solve but myopic (it can't see task costs beyond $H$ steps ahead, e.g. a target only reachable via a detour); a long horizon approaches the true infinite-horizon optimal policy (DYN-04's stationary $V(x)$) but costs more to solve every cycle.
- **Terminal cost**: replacing the truncated horizon's missing "tail" with a good estimate of the true cost-to-go mitigates short-horizon myopia without the cost of a long horizon. The natural choice is DYN-04's own infinite-horizon value function: for the LQ case, $\phi(x_H):=x_H^\top Px_H$ (the Riccati solution) as the terminal cost makes a short-horizon MPC solve approximate the true infinite-horizon optimal policy far more closely than a horizon with no terminal cost at all (equivalently $\phi\equiv0$, i.e. pretending the world ends at step $H$).
- **Warm-starting**: consecutive MPC solves are nearly identical problems (the same trajectory, shifted by one step, with a slightly updated $x_0$), so initializing each new solve with the *previous* solution (shifted forward by one step, with one new step appended, e.g. by repeating the last control) gives OPT-01/OPT-02's Newton-type solvers an initial guess that's already close to optimal, letting each re-solve converge in far fewer iterations than solving from scratch, which is often what makes real-time re-solving computationally feasible at all.

## Summary

- Executing a single open-loop trajectory-optimization solution (DYN-04) is fragile: model error and disturbances make the actual state drift from the plan, and precomputed controls don't correct for it.
- **MPC** fixes this by re-solving DYN-04's finite-horizon problem at every control cycle from the true current state, applying only the first control each time, exactly generalizing DYN-05's per-cycle timing re-solve to a full trajectory.
- Because it's re-solved from the true state every cycle, MPC's applied control is a genuine state-feedback policy $\pi_{\text{MPC}}(x,t)$, DYN-06's closed-loop structure, not an open-loop plan; this is exactly what gives it robustness to model error.
- Horizon length trades cost against foresight; a terminal cost built from DYN-04's infinite-horizon value function (e.g. the LQR $x^\top Px$) mitigates short-horizon myopia; warm-starting each solve from the previous (shifted) solution makes real-time re-solving computationally tractable.
