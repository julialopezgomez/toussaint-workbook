## Why this matters

PLAN-02's PRM/RRT algorithms both assume a local planner can connect *any* two nearby configurations, e.g. a straight line. DYN-01's dynamics already violate this silently: a robot with mass can't instantly jump to any velocity, its motion is constrained by its own current state. This module makes that constraint precise (**non-holonomic**), shows exactly how it breaks naive sampling-based planning, and derives the fix.

## Holonomic vs. non-holonomic constraints

A **holonomic constraint** has the form $h(q,t)=0$ (a $d$-dimensional constraint function directly restricting which configurations $q$ are feasible; PLAN-01's closed-kinematic-chain example). Introducing coordinates that satisfy such a constraint is not minimal: the true degrees of freedom are $p=n-d$ (PLAN-01).

A **non-holonomic constraint** has the more general form $h(q,\dot q,t)=0$: a restriction not on which *configurations* are reachable, but on which *velocities* are achievable at a given configuration. Toussaint's own version of this idea, stated directly in terms of controls: for a controlled system $\dot x=f(x,u)$, define the **tangent space generated by controls** at state $x$,

$$U_x := \{\dot x : \dot x=f(x,u),\ u\in U\}$$

A system is **non-holonomic** iff $\dim(U_x)<\dim(x)$: not every direction of instantaneous motion is achievable, only those spanned by the available controls. (Dynamic systems, DYN-01's subject, are automatically non-holonomic in this sense: the state $x=(q,\dot q)$ can't instantaneously change $q$ independent of the current $\dot q$.)

<ExerciseCard id="PLAN-03-ex1-holonomic-definitions-conceptual" />

**A subtlety worth knowing (not usually relevant in practice)**: some constraints written as $h(q,\dot q,t)=0$ *look* non-holonomic but are actually **integrable**, meaning the reachable configurations, once you trace through all feasible velocity trajectories, actually lie on a sub-manifold describable by an equivalent holonomic constraint $h(q,t)=0$ after all. Deciding whether a given constraint is truly non-holonomic or merely integrable in disguise requires the Pfaffian-form machinery from the broader nonlinear-control literature; genuinely rare in typical robotics settings, so this workbook doesn't develop it further, but it's worth knowing the distinction exists.

## The car (bicycle) model

The canonical non-holonomic example. State $q=(x,y,\theta)$ (position and heading), controls $u=(v,\phi)$ (speed and steering angle, $|\phi|<\Phi$), wheelbase $L$:

$$\dot x = v\cos\theta, \qquad \dot y = v\sin\theta, \qquad \dot\theta = \frac{v}{L}\tan\phi$$

<ExerciseCard id="PLAN-03-ex2-car-constraint-derivation" />

$$\dot x\sin\theta - \dot y\cos\theta = 0$$

This is a genuine non-holonomic constraint: it restricts the *velocity* direction at every $q$ (motion is only possible along the heading direction, never sideways: "a car cannot move directly lateral"), while every $(x,y,\theta)\in\mathbb{R}^2\times S^1$ remains individually *reachable* eventually (with enough maneuvering, as anyone who has parallel-parked knows). This is exactly the dynamic-system analogy from DYN-01: just as a car can't instantly move sideways, a dynamic system can't instantly jump its position independent of its current velocity.

A PRM/RRT built in the raw configuration space $(x,y,\theta)$, using a straight-line local planner, will happily connect two configurations even when no achievable control sequence actually links them, exactly PLAN-02's local-planner assumption breaking down. The fix is **control-based sampling**: instead of connecting configurations directly, extend the tree by picking actual controls and simulating forward:

```
Control-based-sampling(tree T of configurations):
  1: select a configuration q from tree T
  2: pick a control vector u at random
  3: integrate the equations of motion forward from q, using u, for a short duration
  4: if the resulting motion is collision-free, add the endpoint to the tree
```
*(Marc Toussaint, `Lecture-Robotics.pdf`, p.84, §4.3:52.)*

Every edge produced this way corresponds to an actually-executable control, by construction, at the cost of losing PLAN-02's nice space-filling exploration property (random controls don't explore as evenly as random target sampling did). **RRTs with differential constraints** recover a version of that exploration property, by still sampling a random *target* but using a local planner (rather than a random control) to steer toward it:

```
RRT-with-differential-constraints(q_start, k nodes, time interval τ):
  Input:  q_start, number k of nodes, time interval τ
  Output: tree T = (V, E)
  1: initialize V = {q_start}, E = ∅
  2: for i = 0 : k do
  3:     q_target ← random sample from Q
  4:     q_near ← nearest neighbor of q_target in V
  5:     use a local planner to compute controls u that steer q_near toward q_target
  6:     q_new ← q_near + ∫₀^τ q̇(q, u) dt
  7:     if q_new ∈ Q_free then V ← V ∪ {q_new}, E ← E ∪ {(q_near, q_new)}
  8: end for
```
*(Marc Toussaint, `Lecture-Robotics.pdf`, p.87, §4.3:58.)* Two questions this raises, both genuinely hard: how do you measure "near" for a system whose reachable directions are constrained (a plain Euclidean distance can badly misjudge how *hard* it actually is to reach a nearby-looking configuration), and how do you find controls $u$ that steer toward a target at all?

## Configuration-space metrics

The "how do you measure near" question needs a genuine metric on the configuration space, and Euclidean distance on raw coordinates is often wrong for orientation components:

- **2D rotations** $\theta_1,\theta_2\in SO(2)$: either the Euclidean distance between $e^{i\theta_1},e^{i\theta_2}$, or directly $d(\theta_1,\theta_2)=\min\{|\theta_1-\theta_2|,\,2\pi-|\theta_1-\theta_2|\}$ (the shorter way around the circle).
- **Planar poses** $(x,y,\theta)\in\mathbb{R}^2\times SO(2)$: Euclidean metric on $(x,y,e^{i\theta})$.
- **3D rotations** $r_1,r_2\in SO(3)$, represented as unit quaternions (KIN-02): $d(r_1,r_2)=\min\{|r_1-r_2|,|r_1+r_2|\}$, taking the minimum over the two sign choices since $r$ and $-r$ represent the identical rotation (exactly the double-cover fact from KIN-02).
- The genuinely **ideal** metric would be the true optimal cost-to-go between two states (DYN-04's value function): but computing that is, in general, exactly as hard as solving the original planning problem, so in practice it's approximated (e.g. by neglecting obstacles).

**Dubins curves** give a cheap and useful approximation for a car-like system moving at constant speed: neglecting obstacles, exactly six trajectory types (combinations of left/right-turn arcs and straight segments, $\{LRL,RLR,LSL,LSR,RSL,RSR\}$) suffice to connect any two configurations in $\mathbb{R}^2\times S^1$ optimally, giving a genuine, efficiently-computable **Dubins metric** for RRT nearest-neighbor queries (and directly usable as the local planner's steering controls too). **Reeds-Shepp curves** extend this to cars that can also reverse (46 trajectory types), a better metric whenever backward motion is allowed.

## Summary

- **Holonomic** constraints $h(q,t)=0$ restrict configurations directly; **non-holonomic** constraints $h(q,\dot q,t)=0$ restrict achievable velocities. Toussaint's equivalent framing: non-holonomic iff $\dim(U_x)<\dim(x)$, the tangent space generated by controls is smaller than the full state space.
- The **car model** is the canonical example: $\dot x\sin\theta-\dot y\cos\theta=0$ forbids lateral motion at every instant, even though every configuration remains eventually reachable.
- PRM/RRT built directly in $(x,y,\theta)$ can produce physically-infeasible paths; **control-based sampling** (simulate forward from real controls) and **RRTs with differential constraints** (steer toward a random target via a local planner) fix this.
- Configuration-space metrics for orientations need care (angular/quaternion distance, not raw Euclidean); the *ideal* metric (true optimal cost-to-go) is as hard as planning itself, so cheap approximations like **Dubins/Reeds-Shepp curves** are used in practice.
