## Why trajectory optimization alone can fail

Recall DYN-04's trajectory-optimization cost, directly reusing its own notation:

$$f(q_{0:T}) = \sum_{t}\|q_{t-1}-q_t\|_W^2+\sum_t\|\Phi_t(q_t)\|^2$$

Suppose you initialize this optimization with the straightforward guess: a straight line from $q_\text{start}$ to $q_\text{goal}$. If an obstacle sits between them, the task-cost term $\Phi_t$ (via a collision/clearance penalty) creates a smooth but genuinely local cost landscape around that straight line; gradient-based optimization (Gauss-Newton, OPT-02) will happily push the trajectory to locally reduce collision cost, but has no mechanism for discovering it should route *all the way around* the obstacle rather than locally nudging through or against it. This is PLAN-01's local-minimum problem again, now in trajectory space instead of potential-field space: exactly the same failure mode, one level up.

## The two-stage pipeline

The standard fix, and the practical reason PLAN-02/PLAN-03 exist at all: use a sample-based path finder (PRM, RRT) to solve the **global, topological** sub-problem first (which side of each obstacle, i.e. which homotopy class of path), producing *some* feasible, if jagged and non-smooth, path; then hand that path to DYN-04's trajectory optimization as its **initial guess**, letting local optimization do what it's actually good at: smoothing, respecting dynamics/non-holonomic constraints (PLAN-03), and locally minimizing control effort, all without ever needing to solve the hard global search problem itself.

<ExerciseCard id="PLAN-04-ex2-pipeline-conceptual" />

This is precisely why PLAN-02's algorithms only need to find *some* feasible path (they explicitly don't optimize path quality much, e.g. RRT's raw output is visibly jagged, PLAN-02's own figure shows this) and why DYN-04's cost function never needs to reason about *global* topology (it can safely assume its initial guess is already on the right side of every obstacle): the two stages divide the problem exactly along the local/global line PLAN-01 first drew.

## Summary

- Trajectory optimization (DYN-04) alone can fail via local minima, exactly PLAN-01's local-minimum problem one level up: it has no mechanism for discovering which side of an obstacle to route around.
- The standard fix is a **two-stage pipeline**: sample-based path finding (PLAN-02/PLAN-03) solves the global, topological feasibility problem once; trajectory optimization then locally refines that path into something smooth, dynamically feasible, and locally optimal.
- This division of labor is exactly why PLAN-02's algorithms don't need to optimize path quality, and why DYN-04's cost function doesn't need to reason about global topology: each stage does only what it's actually suited for.
