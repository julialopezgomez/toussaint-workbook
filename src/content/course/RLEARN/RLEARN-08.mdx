## Why this matters

This closing module is deliberately a lighter, survey-level tour (Tier 3, matching the curriculum's own scope for it): multiple robots introduce a genuinely new structural problem, **a time-varying number of other agents to reason about**, that every earlier module in this workbook implicitly assumed away by considering a single robot in a (mostly) static environment.

## Handling a dynamic number of neighbors

A distributed collision-avoidance policy, $f(Y)\mapsto u$ with $Y$ the set of observed neighbors, needs to handle a **dynamic, unordered** input: the number of neighbors changes over time, and there's no natural ordering among them (swapping two neighbors' labels shouldn't change the output). Simple fixes (feed neighbors into an LSTM, or encode them as an image for a CNN) work but don't structurally guarantee permutation invariance.

**Deep Sets**: any continuous, permutation-invariant function of a set can be approximated as

$$f(X) \approx \rho\Big(\sum_{x\in X}\phi(x)\Big)$$

<ExerciseCard id="RLEARN-08-ex1-deepsets-numeric" />

(learn a per-element representation $\phi$, sum it, then decode with $\rho$); a heterogeneous extension (Neural-Swarm2) uses a separate $\phi$ per neighbor *type* and a separate $\rho$ per receiving-agent *type*, still only needing $O(K)$ networks for $K$ types, however many actual neighbors exist.

**Graph Neural Networks (GNNs)**: generalize Deep Sets to a full graph $G=(V,E)$, learning $D$-dimensional per-node features $h_n^{(l)}$ across $L$ layers via **aggregate** (combine neighbor features, e.g. $\text{MLP}_\rho\big(\sum_{m\in N(n)}\text{MLP}_\phi(h_m^{(l)})\big)$, a Deep-Sets-shaped aggregation over each node's neighborhood) and **update** (combine a node's own previous feature with the aggregated neighbor information, e.g. $f(W_\text{self}h_n^{(l)}+W_\text{neigh}z_n^{(l)}+b)$).

<ExerciseCard id="RLEARN-08-ex2-gnn-conceptual" />

**A recurring case-study pattern**: train a decentralized policy to imitate a centralized expert (a centralized multi-robot motion planner, or a centralized collision-avoidance solver), via behavior cloning and/or DAgger (RLEARN-02), exactly the privileged-teacher idea again, now with "privileged" meaning "has access to everyone's state at once," not just richer sensing.

## Multi-Agent Reinforcement Learning (MARL)

RL-01's single-robot MDP $(S,A,P,R,P_0,\gamma)$ generalizes to a **Markov game** $(N,S,A,P,R,P_0,\gamma)$: $N$ robots, a *joint* state space $S$, joint action space $A=A_1\times\cdots\times A_N$, and $N$ (possibly distinct) reward functions $r_1,\ldots,r_N=R(s,a)$.

<ExerciseCard id="RLEARN-08-ex3-markov-game-conceptual" />

**Reward structures**: fully cooperative ($r_1=\cdots=r_N$, no credit assignment between agents, but genuinely hard to train); competitive (zero-sum, $\sum_ir_i=0$); mixed cooperative-competitive (local reward shaping toward a shared goal, teams competing against other teams). **Training/execution paradigms**: fully centralized (treat the whole team as one big "stacked" robot); fully independent (each agent learns its own policy with no coordination at all); **Centralized Training, Decentralized Execution (CTDE)**, train with full information access, deploy each agent using only its own local information, the multi-agent analogue of RLEARN-04's privileged-teacher pattern.

**Core challenges**: **non-stationarity** (if other agents' policies aren't directly observable, the environment appears non-Markovian from any single agent's perspective, since "the same state" can now lead to different outcomes depending on what the *other*, unobserved agents are currently doing); **scalability** (in standard policy-gradient methods, the probability of estimating the gradient correctly can decrease exponentially with the number of agents). Standard approaches: a centralized critic (MADDPG), factorized value functions (Value Decomposition Networks), or explicit communication-learning (train agents what to communicate, not just how to act).

## Summary

- **Deep Sets** ($f(X)\approx\rho(\sum_x\phi(x))$) and their **GNN** generalization give permutation-invariant, variable-cardinality architectures for a changing number of neighbors, both trainable with the same DAgger/behavior-cloning tools already covered.
- **Markov games** generalize RL-01's MDP to $N$ agents with a joint action space and per-agent rewards, spanning fully cooperative to fully competitive reward structures.
- **Non-stationarity** (other agents' unobserved policy changes break the Markov property) and **scalability** (gradient-estimation quality degrading with agent count) are MARL's two core challenges; **CTDE** is the standard practical compromise between centralized and independent training.
